# 大规模压测数据注入设计

## 目标

为 PostgreSQL 测试库提供可重复的大规模数据生成能力：节点、服务、遥测快照和事件各至少 10,000 条，用于验证分页、筛选、概览和前端大数据量展示。生成的数据仅用于压测与演示，不作为真实故障评测或验收证据。

## 边界与安全约束

生成器是独立命令行脚本，必须显式提供 `--database-url` 和 `--confirm-load-data` 才能写入。脚本拒绝没有确认标志的执行，且不创建用户、认证凭据、审批动作或动作执行记录。

所有生成记录使用唯一前缀：`load-node-`、`load-service-`、`load-inc-`。清理模式只能删除带这些前缀的记录及其数据库级联关联，不得执行无条件删表、清库或按非前缀条件删除。

## 数据模型与规模

默认 `--count 10000`，并可通过 `--count` 提高数量。每次成功运行分别写入：

- 至少 `count` 个 `nodes`；
- 至少 `count` 个 `services`，每项关联一个生成节点；
- 至少 `count` 个 `telemetry_snapshots`，每项关联一个生成节点；
- 至少 `count` 个 `incidents`，每项关联一个生成节点。

现有遥测表以 `node_id` 作为主键，因此生成器写入的是每个节点的最新遥测快照，不伪造不存在的历史遥测序列。

## 可重复性与数据分布

脚本接受 `--seed`，默认固定为 `42`。相同的数量和种子必须生成相同 ID 与指标分布。节点状态、服务类型、CPU/内存/磁盘指标、事件严重度和事件状态使用确定性轮换，覆盖在线与离线节点、常见服务类型及不同事件视图，避免所有记录完全相同。

写入使用可配置的 `--batch-size`，默认 1,000；每个批次在同一事务中提交。重复执行默认以相同主键更新或保持已有压测记录，而不是制造重复主键异常或扩张到不可控数量。

## 命令接口

```powershell
python tools/seed_load_data.py `
  --database-url "postgresql+psycopg://..." `
  --confirm-load-data `
  --count 10000 `
  --seed 42 `
  --batch-size 1000

python tools/seed_load_data.py `
  --database-url "postgresql+psycopg://..." `
  --confirm-load-data `
  --purge
```

`--purge` 不接受 `--count` 作为删除范围；它只清理带压测前缀的数据。命令完成后输出每类记录的实际数量和写入/删除结果。

## 验证

集成测试使用临时 SQLite 数据库验证：缺少确认标志时拒绝写入；注入后四类记录均达到请求数量且外键关联有效；相同参数重跑数量不膨胀；清理后仅压测前缀记录被移除，非压测记录仍存在。真实 PostgreSQL 的 10,000 规模执行作为手动压测步骤记录在文档中。
