# 工程质量门禁补全设计

## 目标与边界

本次只补齐仓库内能够独立验证的工程质量能力：持续集成、前端测试输出治理、前端构建分包和验证文档。不接入镜像仓库、不发布制品，也不把真实银河麒麟、Ascend、MindIE、120 次盲测或断网重装的结果伪造成自动化验收。

## 方案选择

采用最小可合并质量门禁方案。GitHub Actions 在推送和 Pull Request 时执行 Python 测试与 Ruff、OpenAPI TypeScript 客户端再生成后的无漂移检查、前端测试、前端 Lint 和生产构建。该方案不依赖数据库、Redis、浏览器服务或外部密钥，适合在公共 CI 环境稳定运行。

## 持续集成

工作流使用 GitHub 托管的 Ubuntu 环境，分别建立后端与前端任务。后端任务安装 Python 3.11 与项目开发依赖，执行 `pytest` 和 `ruff check .`。前端任务安装 Node.js 与 pnpm，使用锁文件安装依赖，执行 API 客户端生成、确认 Git 工作树无变化、执行前端测试、Lint 和构建。

生成检查必须在 `generate:api` 后通过 `git diff --exit-code`。这使 OpenAPI 文档与生成类型的偏差直接阻止合并，避免运行时契约失配。

## 前端测试输出

测试初始化文件将针对 JSDOM 已知不支持的 CSS 样式解析和伪元素 `getComputedStyle` 调用提供最小兼容处理。兼容处理只作用于测试环境，不修改生产运行时，也不吞掉未知的控制台错误。

验收标准是前端测试命令退出成功，且不再输出已知的 CSS 解析或伪元素计算样式告警。

## 构建分包

Vite 使用明确的 `manualChunks` 划分：React 运行时、Ant Design、React Flow，以及其余第三方依赖。业务页面继续通过现有路由懒加载，不为了压缩数字改变页面行为。

验收标准是生产构建成功，入口业务包不再包含上述大型第三方运行时；如果仍存在超限提示，以真实构建输出记录为准，不通过调整警告阈值隐藏问题。

## 验证文档

`docs/test-report.md` 将记录新增的本地命令与 CI 覆盖范围，并把真实环境验证保留为阻塞交付条件。文档不能宣称未实际执行的硬件、数据库、离线或盲测结果。

## 非目标与后续

Playwright 端到端测试、覆盖率阈值、容器镜像构建、Compose 运行时冒烟、镜像发布和真实硬件验收不在本次范围。它们需要稳定的服务依赖、密钥或目标设备，应作为后续独立工作项。
