# 大规模态势总览、审计与事件筛选设计

## 目标

在包含 10,000 个节点、服务、遥测快照和事件的隔离压测库中，保证态势总览首屏稳定可用；让压测数据注入与清理在审计日志中可追溯；让事件中心能够通过服务端筛选快速定位事件。

## 非目标

- 不在总览中绘制全部物理节点或全部依赖边。
- 不为每一条压测数据创建独立审计记录。
- 不改变生产环境的 CORS 边界或现有角色权限。

## 聚合态势总览

`GET /api/v1/overview` 新增聚合拓扑摘要。后端以数据库聚合查询按服务类型和节点状态计算数量，并按服务类型汇总依赖关系；总览接口不再为压测规模加载、序列化或返回所有节点和遥测快照。

摘要中的每个聚合节点至少包含稳定标识、服务类型、状态、节点数量和用于节点明细页的筛选条件。聚合边只表达服务类型之间的依赖数量与置信度，不携带逐节点边。

前端在有聚合摘要时使用聚合节点绘制拓扑，数量和状态直接显示在节点卡片中。点击聚合节点后跳转到资源管理的节点列表，并通过 URL 查询参数携带服务类型和状态。低数据量或内存演示模式保持现有物理节点拓扑的兼容展示。

## 审计日志

压测脚本完成写入后记录一条 `system.load_data_seeded` 审计日志；完成清理后记录一条 `system.load_data_purged` 审计日志。记录的操作人固定为系统主体，目标为压测数据集，详情仅包含数量、随机种子和批大小等非敏感运行参数。

审计记录与同一次压测写入或清理在同一数据库事务中提交。失败或被安全保护拒绝时不产生成功审计记录。已有管理员创建、更新、归档等审计行为不变。

## 事件中心筛选

事件列表接口在既有分页、状态和来源筛选基础上，新增严重级别、节点/标题关键词和开始时间范围参数。所有条件在数据库查询中执行，并以 `started_at` 倒序分页，避免把全部事件载入内存后筛选。

前端筛选栏包括状态、严重级别、来源、节点/标题关键词、开始时间范围和重置操作。任何筛选变化都会回到第一页并组成新的查询键；选中详情在不再属于结果集时清空。筛选值同步到 URL 查询参数，刷新或分享链接后保留。

## 错误处理与权限

- 聚合或筛选参数不合法时由 FastAPI 参数校验返回 `422`。
- 审计日志仍只允许管理员读取。
- 事件筛选保持管理员、操作员和只读用户可读的现有权限。
- 聚合查询出现空数据时返回零数量摘要，前端显示空状态而不渲染空白画布。

## 验收与测试

- 10,000 条压测数据下，概览响应不包含 10,000 个物理节点，并可返回正确的状态与服务类型计数。
- 写入和清理分别只新增一条对应的系统审计日志。
- 组合筛选返回正确总数、顺序和分页，不匹配条件时返回空页。
- 前端筛选操作生成正确请求、重置恢复默认列表，聚合拓扑不渲染物理节点集合。
