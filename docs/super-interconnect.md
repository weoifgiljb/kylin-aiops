# 超级互联与远程桌面（规划）

本文区分两项能力，避免答辩/方案把「节点运维通道」和「图形远控」混成一套旧栈（例如以 Guacd 为主卖点）。

| 能力 | 定位 | 本期状态 |
| --- | --- | --- |
| **超级互联** | 中心 ↔ 节点 Agent 的运维通道 | **主能力**，对齐当前仓库实现 |
| **远程桌面** | 浏览器内图形桌面会话 | **二期可选扩展**；选定方案 **B：WebRTC 桌面流** |

当前 MVP 边界见 [architecture.md](./architecture.md) 与根目录落地计划：本期不建设远程桌面，也不把 Guacd 写进主架构。

---

## 1. 超级互联（主能力）

### 1.1 要解决什么

校内多台银河麒麟节点上线后，中心需要稳定地：

- 接收节点心跳与采集数据；
- 下发**已审批、已签名**的白名单动作；
- 在控制台观测节点/事件，并留下审计。

这是 **Agent 互联**，不是 HTML5 远程桌面网关。

### 1.2 技术栈（对齐本仓库）

| 层 | 选型 | 职责 |
| --- | --- | --- |
| 节点 | `agents/ops-agent`（Python） | **主动 mTLS** 接入中心；采集；拉取签名动作并本地执行（固定 argv / `shell=False`） |
| 控制面 API | `services/ops-api`（**FastAPI + Uvicorn**） | RBAC、审批、签名、审计、Agent 接口 |
| 业务库 | **PostgreSQL** | 节点、事件、证据、动作、审计等唯一业务状态源 |
| 动作投递 | **Redis**（按节点隔离的 List） | 已批准动作投递给目标节点；Agent `LPOP` 只取本节点队列 |
| 控制台 | `apps/web`（**React + Vite + Ant Design + TanStack Query**） | 观测、审批、拓扑；当前以轮询刷新为主 |
| 推送演进（可选） | SSE / WebSocket | 事件推送可演进，**不改变**「Agent 主动拉动作」的安全模型 |

### 1.3 安全边界（必须保持）

- Agent **不监听**远程控制端口，只主动上报/拉动作。
- 动作链：白名单参数 → 人工审批 → HMAC 签名 → 目标验签 → 过期/幂等 → 前置检查 → 执行 → 健康检查 → 审计。
- 超级互联 **不等于** 任意远程 Shell，也 **不等于** 桌面远控。

### 1.4 卡片文案（可直接用于 PPT）

**超级互联**  
节点 `ops-agent` 经 mTLS 主动接入；中心 FastAPI + Redis 下发签名动作；控制台 React 统一观测与审批。按 Agent 集群水平扩展，支撑千级节点在线。

## 2. 远程桌面（二期可选 · 方案 B WebRTC）

> **规划文档**：以下接口与组件**尚未在本仓库实现**，不得写成「已上线」。与超级互联控制面共用鉴权/审计思路，**数据面分离**。

### 2.1 为什么选 B 而不是 Guacd 主路径

| 方案 | 说明 | 本仓库态度 |
| --- | --- | --- |
| A Guacamole / guacd | RDP/VNC HTML5 网关，信创场景常见 | 仅可作**旧环境兼容备选**，不作主卖点 |
| **B WebRTC 桌面流** | 控制面自研票根+信令；媒体走 WebRTC | **选定的演进方向** |
| C xterm.js Web 终端 | 仅字符终端，不是图形桌面 | 若只要 Shell，另开能力，勿称远程桌面 |

### 2.2 技术栈

| 层 | 选型 | 职责 |
| --- | --- | --- |
| 控制台 | React + **`RTCPeerConnection`（WebRTC）** | 播放桌面流、回传键鼠 |
| 控制面 | `ops-api`（FastAPI） | RBAC、**短时会话票**、会话审计、废票 |
| 信令 | FastAPI **WebSocket**（或 SSE） | 仅交换 SDP/ICE 等信令，**不传视频** |
| 会话状态 | PostgreSQL + Redis | 会话记录、票根 TTL、在线状态 |
| 节点数据面 | Agent **旁路**桌面采集/编码进程 | 采屏编码后经 WebRTC 出站 |
| 媒体 | **WebRTC** | 低延迟音视频与输入通道 |
| 穿透 | STUN；校内 NAT 可选 **TURN** | 连不通时中继 |
| **明确不采用** | 以 Guacd 为唯一/主数据面 | 避免把平台叙事绑死在旧远控中台 |

### 2.3 链路（口述）

1. 控制台向 `ops-api` 申请桌面会话 → RBAC 校验 → 发放短时 ticket。  
2. 浏览器与节点经中心完成 **WebRTC 信令**握手。  
3. 节点旁路推流；**媒体不经过业务 API 主机**（点对点或经 TURN）。  
4. 断线或过期废票；操作写入审计。

### 2.4 安全硬条件

- 桌面入口必须过中心票根，禁止把桌面网关/guacd **裸暴露**公网。  
- 审计至少包含：操作者、目标节点、起止时间、会话 ID。  
- 桌面通道与**白名单动作执行链隔离**：能看桌面 ≠ 能绕过审批执行任意动作。

### 2.5 规划接口草稿（非契约，实现前须进 OpenAPI）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/desktop/sessions` | 申请会话，返回 `session_id` + 短时 ticket |
| `DELETE` | `/api/desktop/sessions/{id}` | 主动结束/废票 |
| `WS` | `/ws/desktop/signal/{session_id}` | WebRTC 信令 |
| `GET` | `/api/desktop/sessions/{id}` | 会话状态（供审计与控制台） |

正式实现前：先改 FastAPI Schema → `tools/export_openapi.py` → 前端再生成客户端（见 CONTRIBUTING）。

### 2.6 卡片文案（可直接用于 PPT）

**远程桌面（扩展 · WebRTC）**  
控制面：FastAPI 会话票 + WebRTC 信令；数据面：节点推流 + 浏览器 WebRTC 播放。低延迟图形远控与 Agent 运维通道分离，支持审计与票根失效。

## 3. 答辩时如何并列表述

- **超级互联（主）**：`ops-agent` mTLS + FastAPI + Redis 签名动作 + React 观测。  
- **远程桌面（B）**：中心票根/信令 + WebRTC 桌面流（二期）。  
- **不要写**：Guacd 为唯一远控方案；「单机硬扛 1000 路桌面」；把远控说成当前已交付。

### 防追问一句

「视频不进业务 API 机；API 只做鉴权与信令，媒体点对点或经 TURN，避免中心成为带宽瓶颈。」
